# 有限接续、续期与持久监控

## 计算接续：推荐的有限分段链

只有应用支持真实 checkpoint/restart 时才自动接续。`qrerun`/PBS rerunnable 属性不等于应用保存状态。不要把应用崩溃的非零退出统一转成“继续”。

先定义且试验应用协议：

- 一次 segment 在 walltime 减去足够 checkpoint 与收尾余量时主动保存，不能只靠 walltime 到期的 SIGTERM（时间/传播方式依应用和本站而异）。
- checkpoint 先写临时文件，完整校验后原子替换。记录工作流 ID、代码/输入/环境指纹、应用进度、文件 hash 和时间；只有比上次进度更新且可实际恢复才有效。
- 持久应用状态区分 COMPLETE、CONTINUE、FAILED。CONTINUE 只在检查点有效且本段因计划边界正常结束时写入；代码异常/OOM/坏输入为 FAILED。状态文件与 checkpoint 成组一致发布，持有应用锁。
- 每个后继入口检查 STOP、授权截止时间、最大分段、累计请求资源预算、上一段状态与 checkpoint 指纹。COMPLETE 立即退出；FAILED/缺失/陈旧/损坏状态停止并报告；只有有效 CONTINUE 才继续计算。
- 分段序号与预算采用提交前固定计划，不能每次重启清零；不把“完成 epoch 数”当成累计 walltime。按每段请求 CPU/GPU × walltime 预留保守总预算，包括试运行及重试。

实时确认队列支持依赖且配额允许后，可预提交最多 N 段 `qsub -W depend=afterok:FULL_PREVIOUS_ID segment.pbs`。应用按计划 checkpoint 后以 0 退出，由后继 gate 区分完成和待续；意外非零退出不会启动后继。每段保存完整 ID，整链按上述提交幂等机制处理。较早完成后，取消本工作流已排队后继（已授权托管范围内）避免空占资源。

若应用正常 checkpoint 必须返回非零，则先验证其协议，可使用 afterany + 严格 gate；不要直接以 afterany 链接原始命令。失联/硬 walltime 未写出状态时保守停止，用调度器证据与有效 checkpoint 调查后再决定有限恢复。节点故障的恢复也必须先查明状态，不能从“任务消失”直接重跑。

不能 checkpoint 的任务应选择合法长队列、拆成独立子任务或准备资源申请。只有站点明确支持并批准运行中延长时才用其规定命令（如允许的 qalter）；修改失败仍受原 walltime，不能承诺续期成功。

## 认证与权限期限

SSH/VPN 失效按 authentication.md 让用户重新认证。账号、项目、allocation、收费预算分别记录正式到期来源，不能虚构统一续期周期。未知到期不自动按一年推算。

门户存在已批准的自助续期时可按当前授权处理；需 PI/管理员审批、声明或条款时准备材料并交接。没有证实的 API/表单流程时仅提醒和准备申请；发送 A.S.K./邮件需用户明确授权。新额度/新费用超出原边界需确认。

## 数据保留

按实际挂载点记录清理规则和最早风险日期。不将 home snapshot 当作长期备份，不将 Atlas 60 天规则泛化。默认在风险前归档重要 checkpoint/结果到指定持久位置并校验，留出失败重试时间和配额。

若站点有官方数据保留申请/延期机制，先确认适用目录、最长延期和批次数，授权内使用且记录回执/新期限。未经许可不采用 touch、改时间戳或重新复制来规避清理。未知策略从管理员获取，风险未解决时通知，不能报告“已续期”。

## 持久化自动化

用户要求以后持续监控或自动续跑时使用环境可用的官方调度工具；提供 Codex heartbeat 工具的环境优先用它；无头 CLI 未必有该工具。Linux 若已有用户授权的 systemd user timer/其他调度器，可实现同一检查协议；先生成具体配置，用户要求安装后台托管才启用。macOS 后台执行同样需工具或已配置的持久执行器。不能仅写在 skill 中就声称启用。

创建时保存可独立恢复的提示：清单绝对路径；执行主机；SSH alias；有效授权期限/资源预算；所属 workflow/job IDs；只读查询与明确允许的有限接续；提交歧义处理；静默条件；完成/失败/需认证或决策才通知；完成后停止后续恢复。通知机制沿用用户选择，不擅自新增邮件/短信或对外传日志。

建议普通监控每 15 分钟；密码会话复用的空闲期限应覆盖该间隔及调度延迟（默认示例 30 分钟），并单独设置绝对 `auth_deadline`。到期提醒按实际期限设置，使用 Asia/Singapore。只读监控可以认证不可用时通知后退避，但重提交始终先通过认证、清单锁、任务证据和预算 gate。机器休眠/离线、VPN 断开、agent 到期均可能使监控停止，向用户说明。无需持续本地连接的有限 PBS 依赖链更适合无人值守；不默认在登录节点创建 cron/daemon。

验收必须展示调度工具返回的 automation ID/状态及首次可读检查；没有创建成功就明确为“已准备，尚未启用”。

执行器重启/用户注销后，不能假定原 `SSH_AUTH_SOCK`、ControlPath、D-Bus 会话仍存在。任务清单保存可重建的连接配置，不保存 token、私钥或 socket 内容。按 [authentication.md](authentication.md) 分别恢复网络与认证，读取已知 PBS job ID，再处理待提交项；不得在重启后从零重新提交。PID 或旧 socket 文件本身不能证明连接仍有效。
